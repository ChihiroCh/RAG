# 提交文件格式规范（官方口径）

## 文件结构

- `submit-template.xlsx`：Sheet1，固定两列 `id | answer`，共 909 行（1 表头 + 908 题）。
- 提交时**不得改动模板结构**：不增删行列、不改表头、`id` 列保持原值且与题目清单完全一致。
- 输出文件是模板的**副本**（如 `submit-20260501-120000.xlsx`），绝不回写模板本身。

## 题型定义（question_type）

| 题型 | question_type | 任务说明 |
| --- | --- | --- |
| 表格结构恢复 | `structure` | 还原表格行列结构、单元格文本、单元格位置和合并关系 |
| 表格内容提取 | `extract` | 从目标表格中抽取指定单元格、行、列或区域 |
| 表格内容推理 | `thinking` | 先定位相关数据，再完成加总、求差、比例、筛选或排序等简单处理 |

## 结构恢复题（structure）答案格式

**answer 必须是一个合法的 JSON 字符串**，且必须包含 `row_count`、`col_count` 和 `cells`。

### 规则

1. 每个真实单元格**只输出一次**。
2. 横向合并用 `colspan` 表示，纵向合并用 `rowspan` 表示。
3. 被合并覆盖的位置**不需要**额外输出空单元格或占位单元格（合并单元格只输出左上角）。
4. 局部结构恢复（如只恢复前 1 行和前 1 列）仍使用同一个 JSON 结构：
   - `row_count` 和 `col_count` 填写**完整表格的逻辑行数和逻辑列数**；
   - `cells` 只输出题目要求范围内的真实单元格，不需要补全未要求的行列；
   - `row` 和 `col` 仍按完整表格**从 0 开始**编号；
   - `rowspan` 和 `colspan` 仍表示该单元格在完整表格中的真实合并范围。

### 字段说明

| 字段名 | 是否必填 | 说明 |
| --- | --- | --- |
| `row_count` | 是 | 表格逻辑行数 |
| `col_count` | 是 | 表格逻辑列数 |
| `cells` | 是 | 单元格列表 |
| `text` | 是 | 单元格文本 |
| `row` | 是 | 单元格左上角所在行，从 0 开始 |
| `col` | 是 | 单元格左上角所在列，从 0 开始 |
| `rowspan` | 是 | 单元格纵向占用的行数 |
| `colspan` | 是 | 单元格横向占用的列数 |

### 示例：完整结构恢复

```json
{
  "row_count": 4,
  "col_count": 3,
  "cells": [
    {"text": "项目", "row": 0, "col": 0, "rowspan": 2, "colspan": 1},
    {"text": "金额", "row": 0, "col": 1, "rowspan": 1, "colspan": 2},
    {"text": "2025年", "row": 1, "col": 1, "rowspan": 1, "colspan": 1},
    {"text": "2026年", "row": 1, "col": 2, "rowspan": 1, "colspan": 1},
    {"text": "销售额", "row": 2, "col": 0, "rowspan": 1, "colspan": 1},
    {"text": "125000", "row": 2, "col": 1, "rowspan": 1, "colspan": 1},
    {"text": "138000", "row": 2, "col": 2, "rowspan": 1, "colspan": 1}
  ]
}
```

注意：上例第 2 行（row=1）在 col=0 处被 rowspan=2 的"项目"覆盖，因此**不输出**该位置的占位单元格。

### 示例：局部结构恢复（只恢复 row 0 与 col 0）

```json
{
  "row_count": 4,
  "col_count": 3,
  "cells": [
    {"text": "项目", "row": 0, "col": 0, "rowspan": 2, "colspan": 1},
    {"text": "金额", "row": 0, "col": 1, "rowspan": 1, "colspan": 2},
    {"text": "销售额", "row": 2, "col": 0, "rowspan": 1, "colspan": 1}
  ]
}
```

`rowspan=2` 保留是因为"项目"在完整表格中真实纵跨两行，即使当前只恢复局部区域。

## 内容提取题（extract）与内容推理题（thinking）答案格式

- **答案是单个单元格或单个数值**：直接填写最终值（如 `6`、`全场景低代码开发平台`）。
- **答案是一行、一列或一个区域**：填写 **JSON 数组**，数组元素直接填写题目要求的具体值（如 `["188661393.95","46023324.74"]`）；某个值在表格中为空时，该位置填**空字符串** `""`。
- 题目要求多个结果时，使用 JSON 数组。

## 通用答案规范

- `id` 必须与题目清单完全一致。
- 结构恢复题的 `answer` 必须是合法 JSON。
- 结构恢复题中，行列编号从 `0` 开始。
- 局部结构恢复题中，`row_count` 和 `col_count` 仍填写完整表格的逻辑行列数。
- 局部结构恢复题只输出题目要求范围内的单元格，不需要补全未要求的行列。
- 合并单元格只输出左上角单元格，不输出被合并覆盖的位置。
- 文本答案保留原始含义，可以去除多余空格和换行。
- 数字答案去除千分位逗号，例如填写 `125000`，不要填写 `125,000`。
- 日期、金额、百分比和单位按照题目要求填写。
- 如果要求一个数组作为答案，其中某些值在表格中为空，该值填写空字符串。
- 如果题目要求多个结果，使用 JSON 数组。
- 不要在答案中写"根据表格可知""答案是"等说明性文字。

## tests.xlsx 字段说明

| 字段 | 含义 |
| --- | --- |
| `id` | 题目编号，与提交文件 id 一一对应 |
| `file_name` | 来源文件（files/ 下），取主干作为 doc_id 过滤检索 |
| `question_type` | `structure` / `extract` / `thinking`（见题型定义） |
| `question` | 题目 |
| `table_hint` | 表格提示（约 665 题有值），可拼进检索 query 提高召回 |
| `answer_format` | 期望的答案序列化形式：`string` / `number` / `json_array` / `json` |
| `answer` | 空列（竞赛方隐藏的标注），不要读取或依赖 |

`answer_format` 与 `question_type` 的对应关系：`structure` 恒为 `json`；`extract`/`thinking` 为 `string`、`number` 或 `json_array`（单值 vs 数组）。

## 已知数据坑

- 第 903 行附近有一行脏数据：`question_type` 列被问题文本占用（"关键管理人员薪酬…"），按 `answer_format` 处理即可。
- `files/` 中 `002-005.pdf` 是扫描件，其分块来自视觉模型识别，数值可能有 OCR 误差；对 number/json_array 高频出错时可结合 `data/parsed/` 缓存原文核对。
- 视觉模型输出的表格 HTML 常对合并表头补出大量空填充单元格（如 13 物理列实为 3 逻辑列），structure 题需自行收缩空列/空行并只保留真实单元格。
